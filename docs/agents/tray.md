# Tray and hub record

**Tray (Windows).** `lib/tray.js` copies `tray/` to `<hub-dir>/tray` with a `config.json` (port, `app`, version, `server.js` and `node` paths, Run value; the tray derives the hub dir from its own folder), then starts `launch.vbs` → hidden PowerShell `hub-tray.ps1`. `--autostart` also writes `HKCU\...\Run\ClaudeCodeHub-<hash of hub dir>`; the same name keys the tray's single-instance mutex, so a scratch `--hub-dir` gets its own tray and Run value. Stop calls `POST /api/shutdown` and falls back to `taskkill /f /t` after 15 s. The tray writes `<hub-dir>/tray.pid` and deletes it on Quit; `--tray-status` checks it against the image name, because a killed tray leaves it behind. The tray starts the hub through `cmd /c … >> <hub-dir>/hub.log` when no live hub is there, and does not restart a hub that dies. The tray cannot reach an open window, so the hub page holds `GET /api/events` open (`sw.js` lets it pass) and reloads when a new run sends another `boot` id. Open Hub starts the installed app through its Start Menu shortcut (`chrome_proxy.exe --app-id=…` plus `--app-launch-url-for-shortcuts-menu-item=<url with token>`) when the hub runs on `app.port`, else a browser tab. `config.app` is `{id, port: --port}` with `--app-id`, else `{name: 'Claude Code Hub', port: 3540}`.

**Tray (macOS, experimental).** `tray/mac/hub-tray.js` is the same tray as a JXA script run by `osascript`. `--autostart` writes a launch agent to `~/Library/LaunchAgents`. The tray starts the hub with the `PATH` that `--tray` saved in `config.json` (launchd gives a bare one) and `--detached`, which turns off the hub's stop on stdin close. It cannot run on Windows: test it with the dispatch-only `.github/workflows/tray-macos.yml`, which runs `hub-tray.js --self-test` and uploads screenshots and logs.

**Hub record.** Once it listens, the hub writes `<hub-dir>/hub.json` (`pid`, `port`, `lib/hub-record.js`) and removes it on exit when the pid is its own. Before it listens, a hub whose record names a hub that accepts the dir's token on that port prints that hub's URL and exits, so one hub runs per hub dir. The proxies, the hub listener and the stdin watch start only after that check: a closed stdin would end the check halfway. A record left by a killed hub fails the token check. The tray's `Get-Hub` checks the pid only (node, not exited), because it runs every 3 s. Nothing on disk maps an app id to its origin, and Chrome loads any URL into the app, so the port is the only check.
