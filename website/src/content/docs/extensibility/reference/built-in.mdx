The hub ships four tools. This page lists what each tool gives to other apps and what it takes from the hub. For how topics, actions and capabilities work, see [Connect to other tools](/claude-code-hub/extensibility/reference/connect/).

| Tool | Id | Default port |
| --- | --- | --- |
| Kanban | `kanban` | 3541 |
| Marketplace | `marketplace` | 3542 |
| Cost | `cost` | 3543 |
| Memory Diagnoser | `memory` | 3544 |

<BuiltinLinks />

- **Topics.** The hub publishes `project.changed` when you pick a project. Kanban filters its sessions to the project, Marketplace and Memory Diagnoser show that project, and Cost limits its totals to it. Kanban publishes [`session.changed`](#sessionchanged) when you open a session. No built-in tool subscribes to it, but your own apps can, as the Inspector does.
- **Actions.** Kanban calls [`project.plugins`](#projectplugins), [`session.cost`](#sessioncost) and [`project.memory`](#projectmemory) from the session view, and [`agent.cost`](#agentcost) from its CLI. Kanban handles [`session.open`](#sessionopen), [`session.find`](#sessionfind), [`session.paste`](#sessionpaste), [`session.live`](#sessionlive), [`session.new`](#sessionnew), [`task.add`](#taskadd) and [`task.live`](#tasklive). Any app can call them.
- **Capabilities.** The hub reads [`projects`](#projects) and [`terminal`](#terminal) from Kanban.
- **Kept keys.** Kanban keeps <kbd>Ctrl+Alt+N</kbd> (new session), <kbd>Ctrl+Alt+R</kbd> (resume session) and <kbd>Ctrl+Alt+S</kbd> (swap to the previous session) in `keys.keeps`. See [Kept keys](/claude-code-hub/extensibility/reference/manifest/#kept-keys).

A fork or patch wrapper of a built-in tool starts from that tool's manifest. The npm packages of the built-in tools do not include `hub-app.json`. Copy it from the tool's GitHub repository.

## Topics

### `session.changed`

Kanban publishes the session that is open in it.

```json
{
  "sessionId": "d3a7c2e1-5b4f-4c8e-9a12-6f0e8b7d4c31",
  "project": "C:\\demo\\api-gateway",
  "encoded": "C--demo-api-gateway",
  "projectName": "api-gateway",
  "name": "Rate limit for the orders API",
  "gitBranch": "feat/orders-rate-limit",
  "live": false,
  "source": "user"
}
```

| Field | Meaning |
| --- | --- |
| `sessionId` | The session id |
| `project` | The absolute path of the session's project. The hub adds `encoded` and `projectName` |
| `name`, `gitBranch` | The session name and branch, or `null` |
| `live` | True while the session works or waits for the user |
| `source` | `user` for a pick in the Kanban page, `cli` for `claude-code-kanban session open` |

The payload is `null` when no session is open. Kanban publishes it when a pick stays the same for 150 ms, so a move through the list with the arrow keys sends one event. It does not publish it again for the same session.

The [Inspector](/claude-code-hub/extensibility/examples/inspector/) and the [Task board](/claude-code-hub/extensibility/examples/task-board/) subscribe to it.

## Actions

Kanban calls `session.cost`, `project.plugins` and `project.memory` from the session view. It shows each button only when `hub.can()` is true.

### `session.cost`

| | |
| --- | --- |
| Handler | Cost |
| Params | `session?`: a session id |
| URL | `?view=detail&session={session}` |
| Mode | `message` |
| Shows | The cost of that session. With no `session`, Cost comes on screen and keeps its view |

```js
await hub.invoke('session.cost', { session: 'd3a7c2e1-5b4f-4c8e-9a12-6f0e8b7d4c31' });
```

### `agent.cost`

| | |
| --- | --- |
| Handler | Cost |
| Params | `session`: a session id, `agent`: a subagent id (`agent-…`) |
| URL | `?view=detail&session={session}&agent={agent}` |
| Mode | `message` |
| Shows | The cost of one subagent of that session |

```js
await hub.invoke('agent.cost', { session: 'd3a7c2e1-5b4f-4c8e-9a12-6f0e8b7d4c31', agent: 'agent-a10ff4203a47d12a9' });
```

Kanban calls it when `claude-code-kanban session cost <id> --agent <agent id>` names a subagent, and falls back to `session.cost` when no app handles it.

### `session.open`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `session`: a session id |
| Mode | `message` |
| Shows | Kanban comes on screen with that session open |

```js
await hub.invoke('session.open', { session: 'd3a7c2e1-5b4f-4c8e-9a12-6f0e8b7d4c31' });
```

Kanban calls it on itself when `claude-code-kanban new` starts a session, so the hub switches to Kanban before the session opens.

### `session.find`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `name`: words from the session's name, project or branch |
| Mode | `message` |
| Shows | Kanban comes on screen with the session that best matches the words, or its session picker |

```js
await hub.invoke('session.find', { name: 'docs panel' });
```

Kanban scores each session in its list by the share of the words found in its name, project folder and branch. Words of 4 letters or more match on a shared start, so "test" finds "tests". A session that matches at least 60% of the words, 25 points ahead of the next, opens at once. Otherwise Kanban opens its session picker with the words typed in and the best matches first, so <kbd>Enter</kbd> opens the top one. With no match, the picker filters and searches with the words as if you had typed them. The hub's voice control calls it for "Hub, open session …".

### `session.paste`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `text`: the text · `submit`: `"true"` to press Enter after it, optional · `session`: a session id, optional, else the session on screen |
| Mode | `message` |
| Shows | Kanban comes on screen and the text is in the session's input box |

```js
await hub.invoke('session.paste', { text: 'Run the tests', submit: 'true' });
```

The session must run in Kanban's embedded terminal. With no `session`, the text goes to the session whose terminal is on screen; with none on screen, Kanban shows the text in a toast with a Copy button. Claude queues a prompt sent while it works. Kanban refuses the paste, with a toast, while Claude shows a dialog, so Enter cannot answer it. The hub's voice control calls it with dictated text, and `submit: "true"` only when the user pressed Enter during the hold.

### `session.live`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `text`: all the words so far · `final`: `"true"` on the last call · `submit`: `"true"` to press Enter after the last call, optional · `cancel`: on a last call with empty `text`, `"true"` to remove the words and send nothing, `"close"` to also close the New session dialog, optional · `session`: a session id, optional, else the session on screen |
| Mode | `message` |
| Shows | Kanban comes on screen and the words show as they come, in the session's input box or in the New session dialog's Prompt field |

```js
await hub.invoke('session.live', { text: 'Fix the' });
await hub.invoke('session.live', { text: 'Fix the flaky test', final: 'true', submit: 'true' });
```

Each call sends the whole text so far, not only the new words. In the input box, Kanban types keys: it removes with backspaces what changed since the last call and types the rest. While the New session dialog is open and no `session` is named, the text goes into its Prompt field where the cursor was. Until the last call, the dialog glows, shows Listening, and the Prompt is read-only. The last call focuses Start; `submit` does not start the session. With no session on screen, the calls before the last do nothing and the last shows the text in a toast with a Copy button. The same refusal as `session.paste` applies while Claude shows a dialog. The hub's voice control calls it while the key is held.

### `session.new`

| | |
| --- | --- |
| Handler | Kanban |
| Params | All optional, the fields of Kanban's New session dialog: `cwd`: the folder, else the folder of the session on screen, else the project filter · `name` · `prompt`: the first prompt · `worktree`: `"true"` or a worktree name · `model`: `fable`, `opus`, `sonnet` or `haiku` · `effort`: `low` to `max` · `args`: more `claude` args, split on spaces · `edit`: `"true"` to type the command in a shell and wait for Enter · `stay`: `"true"` to start in the background |
| Mode | `message` |
| Shows | Kanban comes on screen with a new session in its embedded terminal |

```js
await hub.invoke('session.new', { prompt: 'Fix the flaky login test', model: 'sonnet', args: '--permission-mode plan' });
```

Kanban does not start the session itself: it opens its New session dialog with these values filled in (with no folder from any of these, the most recent project) and Start focused, so the user sees what starts and presses Enter. Kanban refuses it, with a toast, when the embedded terminal is off. The hub's voice control calls it for "Hub, new session", with the words after it as the prompt.

### `task.add`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `subject`: the task subject, optional; `description`: the task description, optional |
| Mode | `message` |
| Shows | Kanban comes on screen with a new pending task on the board of the session on screen |

```js
await hub.invoke('task.add', { subject: 'Fix the flaky login test' });
```

With no `subject`, Kanban opens its Add task dialog. With no session on screen, Kanban shows a toast and adds nothing.

### `task.live`

| | |
| --- | --- |
| Handler | Kanban |
| Params | `subject`, `description`: the title and description so far, optional · `pending`: `"true"` when the words are done and the last call is on its way · `final`: `"true"` on the last call · `submit`: `"true"` to add the task on the last call, optional · `cancel`: `"true"` to close the dialog and add nothing, optional |
| Mode | `message` |
| Shows | Kanban comes on screen with its Add task dialog, and the fields change as the calls come |

```js
await hub.invoke('task.live', { description: 'The login button does nothing' });
await hub.invoke('task.live', { pending: 'true' });
await hub.invoke('task.live', { subject: 'Fix the login button', description: 'The login button does nothing on Safari', final: 'true' });
```

The first call opens the dialog for the session on screen. Until the last call, the dialog glows, shows Listening, and its fields are read-only; the calls before it change only the description. After `pending`, a last call that takes over 300 ms shows "Writing a title". The last call sets both fields (with no `subject`, it keeps them) and focuses Add, so the user reviews the task and presses Enter. A last call that comes after the user closed the dialog does nothing. The hub's voice control calls it for "Hub, add a task" while the key is held.

## Capabilities

Kanban provides both capabilities. To take one over, see [Capabilities](/claude-code-hub/extensibility/reference/connect/#capabilities).

### `projects`

`GET /api/projects` answers the projects that have sessions, sorted by path:

```json
[
  {
    "path": "C:\\demo\\api-gateway",
    "modifiedAt": "2026-09-29T09:58:00.000Z",
    "worktrees": ["C:\\demo\\api-gateway\\.claude\\worktrees\\fix-auth"]
  },
  { "path": "C:\\Users\\me\\AppData\\Local\\Temp\\scratch", "modifiedAt": null, "temp": true }
]
```

`modifiedAt` is the time of the last session change, or `null`. `temp` is true for a project in a temp folder. A linked git worktree is not a row of its own: it is listed in `worktrees` of its repo's row, and `modifiedAt` covers the repo and its worktrees. Kanban remembers which repo a worktree belongs to after the worktree is deleted. The hub shows the list in the project palette (<kbd>Ctrl+Alt+P</kbd>), and picking a repo selects its worktree sessions too.

### `terminal`

Kanban runs the embedded terminal. `GET /api/terminals` answers `{sessions: [...]}`, one entry for each open terminal. While the list is not empty, the hub keeps that set of apps in its pool when you switch config dirs. `POST /api/apps/kanban/restart` and `POST /api/apps/kanban/stop` answer `409` while Kanban has open terminals, unless the body has `force: true`.
